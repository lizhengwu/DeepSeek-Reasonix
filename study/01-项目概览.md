# Reasonix 项目概览

> Reasonix 是一个用 Go 编写的、配置驱动、支持插件的 **AI 编码 Agent CLI 工具**，类似 Claude Code。

---

## 一、项目结构

```
reasonix/
├── cmd/reasonix/main.go         ← 程序入口
├── internal/                     ← 核心逻辑
│   ├── agent/       Agent 主循环、工具调用推理、会话管理
│   ├── control/     Controller — 传输无关的会话驱动（核心大脑）
│   ├── cli/         Bubble Tea TUI 前端（聊天界面）
│   ├── serve/       HTTP/SSE 服务端
│   ├── provider/    LLM 提供商适配（Anthropic、OpenAI）
│   ├── tool/builtin/ 内置工具集（bash、文件、grep、webfetch 等）
│   ├── skill/       可复用 playbook（技能系统）
│   ├── memory/      分层记忆系统（REASONIX.md 链）
│   ├── plugin/      插件系统（stdio/HTTP MCP 插件）
│   ├── codegraph/   CodeGraph 代码智能引擎集成
│   ├── lsp/         LSP 语言服务器集成
│   ├── sandbox/     沙箱执行安全
│   ├── diff/        Diff 引擎
│   ├── config/      配置加载与迁移
│   ├── boot/        启动编排
│   ├── event/       事件系统
│   ├── command/     斜杠命令
│   ├── hook/        钩子系统
│   ├── permission/  权限策略
│   └── ...          更多辅助包
├── .reasonix/       技能文件存储
├── go.mod           Go 模块定义
├── REASONIX.md      项目记忆文件
└── reasonix.toml    用户配置文件
```

## 二、架构分层

```
┌──────────────────────────────────────────────────┐
│                  前端 Frontend                     │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐  │
│  │ cli/TUI  │  │ serve/SSE │  │ desktop/Wails  │  │
│  └────┬─────┘  └────┬─────┘  └───────┬────────┘  │
└───────┼──────────────┼────────────────┼───────────┘
        │              │                │
┌───────▼──────────────▼────────────────▼───────────┐
│              control.Controller                     │
│         传输无关的会话驱动器                          │
│        统一的 Send / Cancel / Approve 等命令        │
└──────────────────────┬─────────────────────────────┘
                       │
┌──────────────────────▼─────────────────────────────┐
│                   agent.Agent                        │
│        Agent 主循环：执行 → 工具调用 → 压缩 → 继续    │
└──────────────────────┬─────────────────────────────┘
                       │
┌──────────────────────▼─────────────────────────────┐
│                provider / tool / ...                 │
│       LLM 提供商层    内置工具层    插件层            │
└─────────────────────────────────────────────────────┘
```

### 核心设计原则

1. **Controller 即核心** — 所有行为加在 `control.Controller`，而非具体前端，三个前端（TUI/SSE/桌面）一致继承
2. **Cache-first** — 系统 prompt 前缀保持字节稳定，利用 DeepSeek 的自动前缀缓存
3. **一包一事** — 每个 `internal/` 包只负责一件事，用 package comment 说明

## 三、关键模块详解

### 1. 入口 `cmd/reasonix/main.go`

```go
func main() {
    os.Exit(cli.Run(os.Args[1:], version))
}
```
通过 blank import 注册内置 provider 和工具：
- `_ "reasonix/internal/provider/anthropic"`
- `_ "reasonix/internal/provider/openai"`
- `_ "reasonix/internal/tool/builtin"`

### 2. Controller (`internal/control/`) — 大脑

- 职责：管理 Agent 运行循环和会话生命周期
- 接收外部命令：Send（发消息）、Cancel（取消）、Approve（批准工具调用）、SetPlanMode、Compact、NewSession…
- 将一切结果（推理过程、工具调用、审批、turn 完成）发射为类型化事件流
- 不依赖任何前端，可被 TUI / HTTP-SSE / Wails 一致使用

### 3. Agent (`internal/agent/`) — 核心循环

- Agent 主循环：向 LLM 发请求 → 解析响应 → 执行工具调用 → 收集结果 → 继续下一轮
- 结果压缩（compaction）将旧轮次压缩，节省 token
- 分支管理（branch）：支持多轮次的分支结构
- 会话持久化（save/checkpoint）
- 并发控制（spin-off tasks）

### 4. Provider (`internal/provider/`) — LLM 接入

- `provider.Provider` 接口：提供 chat completion API
- **Anthropic** 适配（Claude 系列）
- **OpenAI** 适配（GPT 系列 / DeepSeek 等兼容 API）
- 支持流式响应、思考过程（thinking）提取
- 自动重试

### 5. 工具系统 (`internal/tool/builtin/`)

| 工具 | 用途 |
|------|------|
| `bash` | 执行 shell 命令 |
| `read_file` | 读取文件 |
| `write_file` | 写入/创建文件 |
| `edit_file` | 精确替换编辑 |
| `multi_edit` | 原子性多步编辑 |
| `delete_range` | 按锚点删除范围 |
| `delete_symbol` | AST 删除符号 |
| `grep` | 正则搜索 |
| `glob` | 文件模式匹配 |
| `ls` | 列出目录 |
| `web_fetch` | 抓取网页内容 |
| `task` | 派生子任务（嵌套 agent） |
| `ask` | 向用户问问题 |
| `todo` | 计划跟踪 |

### 6. 技能系统 (`internal/skill/`)

- 可复用的 playbook（playbook），形如 markdown 指令
- 用户可编写新 skill，保存到 `.reasonix/skills/`
- 分为 inline（当前会话内执行）和 subagent（派生子 agent）两种运行模式

### 7. Memory 记忆系统 (`internal/memory/`)

- 层次化文档链：
  - `REASONIX.md`（提交的共享记忆）
  - `REASONIX.local.md`（个人 git-ignored）
  - `~/.config/reasonix/REASONIX.md`（全局记忆）
  - 任意祖先目录的 `REASONIX.md`
- `@path` 语法导入外部文件
- `#<note>` 快速添加笔记
- `remember` 工具持久化事实

### 8. 插件系统 (`internal/plugin/`)

- 支持 **MCP (Model Context Protocol)** 插件
- stdio 传输：启动子进程通过 stdin/stdout 通信
- HTTP 传输：HTTP/SSE 远程插件
- 热添加：`AddMCPServer` 可在会话中动态添加插件
- Lazy / Eager / Background 三种启动时机

### 9. CodeGraph (`internal/codegraph/`)

- 代码智能引擎，基于 tree-sitter + SQLite (FTS5)
- 自动索引项目符号和调用图
- 作为内置 MCP server 启动：`codegraph serve --mcp`
- 提供查询、调用者/被调用者、影响分析等工具
- 首次使用时自动下载缓存（v0.9.7），之后离线即可用

### 10. 启动流程 (`internal/boot/`)

1. 加载配置
2. 选择 provider
3. 初始化 memory 系统
4. 解析 skills
5. 解决 CodeGraph 路径并启动（MCP server）
6. 按 tier (eager/lazy/background) 加载插件
7. 构建 Controller，进入会话循环

## 四、数据流：一次完整的交互

```
用户输入文本
    │
    ▼
Controller.Send(text)
    │
    ▼
Agent.RunLoop:
    ├── 构建 prompt（system prompt + 工具定义 + 消息历史 + 记忆）
    ├── 发送到 Provider (LLM)
    ├── 解析响应（流式文本 / 工具调用）
    ├── 如果是工具调用：
    │   ├── 权限检查（permission 包）
    │   ├── 执行工具（内置工具或 MCP 插件）
    │   ├── 收集结果
    │   └── 回到循环开头（继续下一轮）
    ├── 如果文本回复：输出给用户，turn 结束
    └── 压缩旧轮次，释放 token 窗口
```

## 五、项目特点

- **Go 1.25+** — 使用最新的 Go 语言特性
- **Bubble Tea v2** — 基于 Go 的 TUI 框架（类 Elm 架构）
- **插件化** — MCP 协议支持，可扩展性强
- **多后端** — 支持 Anthropic Claude 和 OpenAI 兼容 API（含 DeepSeek）
- **记忆持久化** — 分层记忆，跨会话保留上下文
- **安全沙箱** — 命令执行权限控制和沙箱
- **代码智能** — CodeGraph 提供代码索引、查询和分析能力
